# Adept knowledge authority

## Purpose

Tell Co-Director which source to trust when two answers disagree.

## Identity

Adept-integrated knowledge. Not a second product. Not upstream marketing.

## Adept integration

When facts conflict, use this order and stop at the first source that actually answers the question:

1. **Live project state** — approved sheets, saved Spatial Map, Library assets, Timeline clips, open project id.
2. **Adept registry** — Production Control rows, capability labels, what this install can run.
3. **This Markdown** — `studio-api/app/codirector/knowledgebase/`.
4. **Installed workflow** — the graph Adept will actually submit.
5. **Upstream docs** — maker guides for MiniMax, LTX, Qwen, and others. Useful for flavor. Not Adept product law.
6. **General LLM knowledge** — last resort. Never overrides Adept.

## Runtime semantics

MODE-SPECIFIC. Authority is always in force. Readiness of a generator does not change this order.

## What Co-Director may read

- The open project's saved records.
- Adept registry labels (Certified, Available, Testing, Requires Setup, On Demand, Not Installed).
- These knowledge files and `MANIFEST.yaml` / `lexicon.yaml`.

## What Co-Director may execute

Nothing from this file alone. Authority only decides which fact wins.

## What Co-Director must confirm

- Costly generation.
- Changing an approved Character, Environment, or Prop sheet.
- Switching the selected generator when the creator named a different one.

## What Co-Director must never claim

- That a blog, a Hugging Face card, or general memory is Adept law.
- That WAN is a current v1.1 generator, or that WAN 2.6 / 3.0, LTX-as-only-T2V, or a circular Spatial Map viewport exist in this product.
- That On Demand means broken.
- That Qwen local can stand in for an Environment Reference Sheet.

## Terminology disambiguation

- **Registry** = Adept's live catalog, not a Hugging Face model card.
- **This Markdown** = Adept-integrated notes. Weaker than live project state.

## Persistence

Authority order is not stored per project. Project facts are.

## Failure semantics

If live project state is missing, say so. Do not invent a character, place, or sheet to fill the gap.
