### 1.2 Transport

- **Request path (unchanged lane):** the eight tools remain `kind="read"` and execute during the turn.
  The service **decorates** the handler result of operator-capable tools with an `operator` block
  (`{requestId, originSessionId, toolId, state:"pending"}`) and appends an `operator_requested` event.
  The existing `tool_completed` SSE event (`service.py:755-760`) carries the decorated result to
  `CoDirectorSession.tsx:1701-1762` — the single frontend reception point. No new chat event type.
- **Ack path (NEW):** `POST /operator/{request_id}/ack` — body `{originSessionId, workspace, target, verified}`.
  Server-verified receipt = the UI actually established the requested state (workspace resolved /
  focus event consumed / tab switched), reported by the frontend after it performs the navigation.
- **Status path (NEW):** `GET /operator/{request_id}` returns the operator record (state, timestamps,
  ack payload). Used by the truthfulness gate and by cross-tab/observability reads.
- **Registration point:** the service read-tool path `_run_read_tool` (`service.py:677`) wraps
  operator-capable tool ids; the wrapper appends the `operator_requested` event (role `assistant`,
  `event_type="operator_requested"`, `request_id`, `tool_result` = decorated result, idempotency key
  `client_request_id = f"operator-req-{request_id}-{tool_id}"`) and returns the decorated result.

### 1.3 State machine + persistence

States: `pending → acknowledged | timeout`. A late ack after timeout is recorded as `operator_late_ack`
event and does NOT upgrade state (truthfulness stays grounded to "requested, not confirmed").

- **Durable record:** append-only events only (`conversation_events.py` `EventInput`): `operator_requested`,
  `operator_acknowledged` (idempotency key `client_request_id = f"operator-ack-{request_id}"`),
  `operator_timeout`, `operator_late_ack`. State is derived by folding the latest operator event for a
  request_id. **No new DB table.** (Law 8: the event log is the single authoritative operator ledger.)
- **In-memory registry (fast path only):** per-process dict `{request_id -> (created_at, state, origin_session_id)}`
  for timeout checking; never the source of truth. Timeout default **3.0 s** (`OPERATOR_TIMEOUT_SEC`),
  configurable by constant. Timeout is evaluated lazily (on ack, on status read) and a best-effort
  background sweep is permitted; the durable `operator_timeout` event is written when first observed.

### 1.4 Pending UX (frontend)

On `tool_completed` whose result carries an `operator` block (or `uiAction`):
- show pending badge keyed by request_id ("Opening X…") via the existing `toolActivity` state
  (`CoDirectorSession.tsx:1699-1709`);
- perform the per-tool navigation (below);
- when the target state is confirmed, POST the ack; clear the badge on ack or on server timeout event
  (or client-side 3 s guard). Stale-turn guard: reuse `activeRequestIdRef` (`CoDirectorSession.tsx:1322`).

`ai-inferred`, `session-only`, `project-persisted`. Frozen field bindings:

|---|---|---|
| `title` | `projects.name` only | creator-stated / creator-approved |
| `format` | `projects.primary_project_type` | creator-stated / system-derived |
| `runtime` | derived from `scenes.duration_sec` / MAGI `durationFrames` | system-derived (never a scalar store) |
| `fps` | `projects.fps` (scene overrides separate) | creator-stated / system-derived |

- **Law 4:** no phase-2 code writes a new persisted stage source.
