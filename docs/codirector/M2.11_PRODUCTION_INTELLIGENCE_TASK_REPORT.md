## Architecture

M2.11 adds a Production Intelligence orchestration layer on top of existing Co-Director intelligence (intent → specialist select → run → synthesize) without replacing M2.7 Production Executive.

| Layer | Role |
| --- | --- |
| Feature flag + M014 | Gate rollout; persist memory, decisions, traces |
| Specialist DAG | Default pipeline Story → Bible → Continuity → Director → Camera → Sound → Music → Editor → QA → User Review |
| Orchestrator | Runs specialists (heuristic-friendly), records decisions/traces, enriches sparse smoke outputs |
| Memory / Decisions / Review loop | Advise-only persistence and Plan→Archive review stages |
| Conflicts bridge | Maps specialist conflict notes into bible conflict surfaces |
| Dashboard API + UI | Collapsible Production Intelligence panel (alongside, not replacing, M2.7 executive) |

Key paths: `m211/orchestrator.py`, `m211/api.py`, `m211/dag.py`, `m211/memory.py`, `m211/decisions.py`, `m211/review_loop.py`, `m211/conflicts_bridge.py`, `m211/platform.py`, frontend `CoDirectorProductionIntelligenceDashboard.tsx`.

## Decision engine

`DecisionRecordStore` persists rationale, confidence, evidence, bible refs, specialist id, approval required/status, recommendation, and explainability JSON. Approval boundaries on bible / continuity / QA / user_review stages record pending approvals **without mutating** bible or timeline.

---

## Memory

`ProductionMemoryStore` upsert/search on `m211_memory_items` (category, tags, scene scope). Used for continuity notes and future retrieval; advise-only.

---

## Explainability

Each orchestrator stage attaches explainability with summary, recommendation, evidence, bibleRefs, specialistId, confidence, stageId, blockingIssues. Surfaces through decisions API and dashboard pending/blocker sections.

---

## Conflicts

`conflicts_bridge.bridge_specialist_conflicts` merges BibleDomainService sync results with specialist-reported conflict/continuity notes. Bible domain routes `/conflicts` and `/conflicts/sync` remain the HTTP surface.
