## What shipped

- **Durable jobs** - SQLite-backed store (not in-memory); append-only attempt/audit history
- **Queue + worker** - status machine `Queued` -> `Waiting` -> `Running` -> (`Paused` | `Blocked` | `Retrying` | `NeedsReview` | `Completed` | `Failed` | `Cancelled`); crash recovery `Running` -> `Retrying` (open attempt closed as `interrupted`)
- **Dependencies** - resolver for closed-loop chain ordering
- **Retries** - attempt budget via retry module
- **Pause / resume / cancel / retry** - service + API endpoints
- **Events** - in-process bus + persisted events (`GET /events`)
- **Notifications** - derived from events (`GET /notifications`)
- **Dashboard** - Co-Director Production Executive UI (7 tabs)
- **Capability blocking** - honest `Blocked` + reason (no fake success)
- **Closed-loop create** - `POST /closed-loop` queues mock chain: `storyboard_generate` -> `image_generate` -> `validate` -> `create_proposal` -> `await_approval` -> `apply_canon`
- **Approval signal** - `POST .../mark-approval` is an external M2.2 signal; responses keep `autoApproved: false`
- **Sync drain** - `POST /worker/drain` for tests/ops

---

## Non-negotiables held

- Orchestration only - no rebuild of Bible / Proposal Bus / Timeline / Refs / Vision / Capability Bridge / Provider Registry
- **No silent approve** - `await_approval` stops at `NeedsReview` until explicit `mark-approval`
- **No silent canon** - `apply_canon` does not invoke Bible mutation APIs; receipt stub with `applied == false`
- **No silent regenerate** - no auto asset regeneration bypass
- M2.2 Proposal -> Review -> Approval path preserved
- Flag default **off**; APIs 404 when disabled
