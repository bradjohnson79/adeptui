# M2.7.1 Integration — Real Service Wiring

## Purpose

M2.7.1 connects the Production Executive closed-loop handlers to real Adept services (in-process), replacing M2.7 mock handlers. Orchestration remains the only Executive responsibility; Bible / Proposal / Timeline / Refs / Vision / Bridge / Registry are not rebuilt.

**Branch:** `phase2/codirector-m2-7-production-executive`
**Flag:** `STUDIO_FEATURE_PRODUCTION_EXECUTIVE_V1` (default **OFF**)

---

## Typed contracts

`studio-api/app/codirector/executive/contracts.py`

- Per-`JobType` input/output Pydantic schemas
- `RetryClass`, `CancellationBehavior`, idempotency key fields, audit event prefix
- Boundary helpers: `validate_job_input` / `validate_job_output` / `audit_metadata`
- Documents that `visualValidationPending` is cleared only by M2.5 VisionEngine when `planId` is set

---

## Handler wiring (closed loop)

`studio-api/app/codirector/executive/handlers.py` — **in-process SQLAlchemy `Session` only; no self-HTTP.**

| Job type | Real service path |
|----------|-------------------|
| `storyboard_generate` | `storyboard_jobs.prepare_storyboard_generate` (+ enqueue helpers) |
| `image_generate` | Job + Asset lifecycle via `imagegen_adapter` (mock path when `ADEPT_MOCK_IMAGEGEN` / `STUDIO_E2E` or Comfy unavailable) |
| `validate` | M2.5 `run_validation` + optional `ReferencePackageBuilder` remap into `ReferenceSetSpec` |
| `create_proposal` | M2.2 `ProposalService.create_proposal` / `get` |
| `await_approval` | Polls proposal status; stays `NeedsReview` until approved or mark-approval adapter |
| `apply_canon` | `ProposalService.approve` only after explicit approval — never silent Bible write |

### ImageGen mock adapter

`studio-api/app/codirector/executive/imagegen_adapter.py`

- Completes deterministic mock ImageGen **through real Job + Asset tables**
- Triggered by `ADEPT_MOCK_IMAGEGEN=1`, `STUDIO_E2E=1`, or Comfy unavailable
- Never invents a fake-only result inside the handler alone

### Validation + refs

- `run_validation(db, ValidateRequest)` from `codirector.vision.engine`
- Optional reference package: `ReferencePackageBuilder(db).build(...)` remapped for vision bindings
- `visualValidationPendingCleared` reported true only when `planId` was set so M2.5 VisionEngine can clear the plan flag

### Proposals / canon

- Create/get via `ProposalService`
- Canon apply **only** via `ProposalService.approve` after explicit approval
- `mark-approval` adapter keeps `autoApproved: false`

---

## Result chaining

`worker._chain_results_to_dependents` propagates closed-loop outputs into dependent job payloads:

`panelId`, `imageJobId`, `assetId`, `proposalId`, `sessionId`, `reportId`, `score`, `passed`, `band`, `proposalApproved`

Dependents see upstream IDs without re-calling HTTP or inventing placeholders.

---

## Non-negotiables

- **Never silent approve** — `await_approval` stops at `NeedsReview`
- **Never silent canon** — no direct Bible mutation; approve path only
- **Never silent regen** — no auto asset regeneration bypass
- **`visualValidationPending`** cleared only by M2.5 VisionEngine when `planId` is set (Executive does not clear it itself)
