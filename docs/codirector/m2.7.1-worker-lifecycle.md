# M2.7.1 Worker Lifecycle

## Model

Honest **single-process** Production Executive worker:

- One daemon thread polls SQLite-backed jobs
- Sync handlers run on that thread
- **`max_concurrent=1`** because handlers are synchronous (no fake parallel fan-out)
- **No distributed leasing** / multi-worker claim protocol — do not document or pretend otherwise

Module: `studio-api/app/codirector/executive/worker.py` (`production_worker` singleton).

---

## Flag-aware lifespan (`main.py`)

When `STUDIO_FEATURE_PRODUCTION_EXECUTIVE_V1` is enabled:

1. **Start** — configure poll interval from `STUDIO_PRODUCTION_EXECUTIVE_POLL_INTERVAL`, then `production_worker.start()`
2. **`start()`** calls `JobStore.recover_running_jobs` so crash-interrupted `Running` jobs become safely retryable
3. **Stop** — on app shutdown, `production_worker.stop()`

When the flag is **OFF**, lifespan does not start the executive worker; job APIs remain 404.

---

## Poll interval

| Env | Behavior |
|-----|----------|
| `STUDIO_PRODUCTION_EXECUTIVE_POLL_INTERVAL` | Float seconds (min ~0.05); default worker poll if unset |

Set in lifespan before `start()`, and readable via `_env_poll_interval()` inside the worker module.

---

## Crash recovery

`JobStore.recover_running_jobs`:

- `Running` → `Retrying`
- Open attempt closed as `interrupted` (append-only history)
- No duplicate silent completion

Covered by pytest `test_crash_restart_recovery_no_duplicate_attempts`.

---

## Drain endpoint (tests / ops)

`POST /api/codirector/jobs/worker/drain` with `{ "maxSteps": N }`

- Synchronously advances the queue without waiting on the background poller
- Returns `{ steps, workerRunning }`
- Primary path for pytest and Playwright API scenarios

---

## Capability checks

`capability.sync_check_capabilities` (worker loop):

- Prefers the **real Capability Bridge** when a Session / project is available
- Honest `Blocked` + reason when requirements are unavailable
- When `ADEPT_MOCK_IMAGEGEN` or `STUDIO_E2E` is set, **`comfyui.health` is treated as available** so closed-loop e2e can proceed through the mock ImageGen Job+Asset adapter (not a fake success for unrelated capabilities)
