# M2.4.1 Capability Unification

**Date:** 2026-07-25  
**Commit intent:** `refactor(codirector): unify tool readiness with capability registry`

## Authority

After PSR merge, capability truth lives in:

- `studio-api/app/capabilities/` (registry + service + probes)
- HTTP: `GET /api/capabilities*`

Co-Director tools must not maintain a parallel readiness matrix.

## Bridge

`studio-api/app/codirector/tools/capability_bridge.py` (`CoDirectorCapabilityBridge`):

1. Maps tool capability keys (`comfyui`, `bible`, …) → PSR capability ids
2. Queries `app.capabilities.service.get_capabilities` for live status
3. Returns `{ tool, status, callable, missingCapabilities[] }` using PSR vocabulary, plus:
   - `proposalReady` — a durable proposal may still be created
   - `executionBlocked` — apply/render cannot proceed with current dependencies

### Status distinctions

| Situation | `status` | `callable` | `proposalReady` | `executionBlocked` |
|---|---|---|---|---|
| All required PSR caps usable | PSR status (e.g. `locally_verified`) | true | true | false |
| Mutating tool; execution deps missing; proposal path ok | `proposal_ready` | false | true | true |
| Neither execution nor proposal path ok | `execution_blocked` / PSR blocker status | false | false | true |

## Adapter

`CapabilityAdapter` keeps the existing `CapabilityState` shape for tool execution callers and E2E mock overrides (`ADEPT_CODIRECTOR_MOCK_SCENARIO`). Live probes delegate to the bridge.

## Scene CRUD

Co-Director scene handlers use PSR `SceneService` (`app/services/scene_service.py`) so patch-only-present-fields and contiguous indices stay consistent with HTTP routes.
