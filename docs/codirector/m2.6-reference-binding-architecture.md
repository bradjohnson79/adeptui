# M2.6 — Timeline Reference Binding Architecture

## Summary

Per-timeline-image **Reference Sets** attach optional supporting assets to Director 2.0 image clips. Primary frames stay on the clip; supporting refs are versioned (copy-on-write) in SQL. Generation consumes a provider-neutral package. Co-Director resolves `@ImageN` and mutates only via M2.2 proposals.

## Components

| Layer | Location |
|---|---|
| Stable tags | `display_tag` + `next_image_tag_number` on director JSON; `director_references/tags.py` |
| Persistence | M007 tables: sets, versions, bindings, presets |
| Service | `director_references/service.py` (item-specific only) |
| Package | `director_references/package.py` |
| REST | `director_references/api.py` under scenes/director/items |
| UI | `TimelineReferencesPanel.tsx` in DirectorTracks |
| Co-Director | tools + context `timeline.images` |
| Vision | optional `ValidateRequest.referenceSet` |

## Inheritance (extension points)

M2.6 is **item-specific only**. Documented future hooks:

- Project defaults → seed from project ingredient packs
- Sequence inheritance → walk editor sequence parents
- Scene ingredients → merge when hierarchy is reliable

## Non-goals

No mandatory refs for Run; no fake IC-LoRA readiness; no clearing `visualValidationPending` outside M2.5; no Captured Video Frame source unless an existing API is end-to-end ready.
