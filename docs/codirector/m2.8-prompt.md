## Final End-to-End Playwright Acceptance

### M2.8 End-to-End Integration Acceptance

After all M2.8 slices are implemented and individually tested, run a dedicated Playwright acceptance phase proving that the complete system is connected end to end.

**This is required before M2.8 may be marked complete.**

Playwright must validate the integrated workflow across:

```text
Model Radar
-> Discovery
-> Registry
-> Compatibility Intelligence
-> Sandbox Plan
-> Approval Boundary
-> Sandbox Runtime
-> Validation
-> Model Routing
-> Production Recipe
-> Adept Virtual Stage
-> Shot Profile
-> Director / Timeline
-> M2.7 Production Jobs
-> M2.5 Vision Validation
-> Human Review
-> Production Bible
```

Do **not** rely only on unit or API tests. The final acceptance must exercise the **user-facing workflow through the browser**.

### Playwright requirements

Use deterministic fixtures and mocked external services where necessary.

CI must **not** depend on:

- live Hugging Face downloads
- live GitHub repositories
- large model files
- paid APIs
- GPU hardware
- ComfyUI production installation
- external provider availability

Use mock discovery responses, small fixture assets, deterministic sandbox simulators, and mock generation providers while preserving the same application contracts used by production.

### Required end-to-end scenarios

Include and fully exercise all 18 scenarios below. Each scenario lists what Playwright must Verify.

#### 1. Feature flags off

Adepts UI loads normally with M2.8 feature flags default off.

Verify:

- Adept UI loads normally
- Existing Director 2.0 and Co-Director workflows remain functional
- Model Radar and Virtual Stage routes are hidden or unavailable
- No browser console errors occur
- No background discovery or sandbox process starts

#### 2. Model discovery to registry

Open Model Radar and run mocked discovery into the unified registry.

Verify:

- Open Model Radar
- Trigger mocked HF discovery
- Trigger mocked GitHub discovery
- Discoveries appear in the unified registry
- Duplicates are suppressed
- Classifications cover official / community / announcement-only / gated / API-only
- Announcement-only entries have no install action

#### 3. Watchlist and compatibility

Select a model, add it to the watchlist, and evaluate compatibility.

Verify:

- Select model
- Add to watchlist
- Compatibility evaluation runs
- Environment profile is used
- VRAM / storage / OS / dependency / license results are shown
- Reasons accompany the verdict
- Unsupported models are not reported ready

#### 4. Sandbox plan approval boundary

Generate an install/sandbox plan and enforce the human approval boundary.

Verify:

- Generate plan with exact files / repos / commits / disk / risks / deps / rollback
- No install occurs before approval
- Reject results in no environment changes
- Approve again creates an M2.7 Production Job or approved execution request

#### 5. Isolated sandbox lifecycle

Create, operate, validate, and remove an isolated sandbox without touching production ComfyUI.

Verify:

- Create sandbox with separate runtime / config / registry / logs / port
- Start sandbox
- Health check succeeds
- Simulate model / custom-node detection
- Validation workflow completes
- Record runtime / mock VRAM / output / warnings / errors
- Stop / restart recovery works
- Remove sandbox
- Production ComfyUI remains unchanged

#### 6. Promotion remains human-gated

Complete sandbox validation and keep promotion human-gated.

Verify:

- Sandbox validation is complete
- Promotion proposal is created
- No production install occurs without approval
- Reject once -- no mutation
- Approve on second attempt
- Promotion manifest records version / commit / hashes / deps / workflow adapter / test env / approval
- Audit history is preserved

#### 7. Co-Director model routing

Ask Co-Director for a plain-language filmmaking outcome and receive routed recommendations.

Verify:

- Project and scene context are available
- Plain-language filmmaking outcome is accepted
- Retrieves project context, Production Bible, Cinematic DNA, available validated models, hardware, and license
- Recommends best model or Production Recipe
- Alternatives are offered
- Reasoning uses filmmaking language
- Technical details are presented separately
- Does not silently change the existing shot model

#### 8. Production Recipe execution

Run a multi-stage Production Recipe through durable M2.7 jobs.

Verify:

- Multi-stage recipe executes
- Each stage is an M2.7 job
- Dependencies are respected
- Dashboard status updates
- Simulate provider failure
- Retry works
- Resume without duplicating successful stages
- Final generation manifest includes every stage

#### 9. Virtual Stage camera workflow

Drive the Virtual Stage camera and persist structured camera values.

Verify:

- Open Virtual Stage
- Scene and Scene Anchor are available
- Orbit works
- Pivot independently
- Elevation / tilt / roll / distance / lens controls work
- Top / side / preview update
- Save camera profile
- Reload preserves structured values
- Prompt instructions are derived from structured data
- Prompt text is not the source of truth

#### 10. Guided and Professional modes

Edit the same Shot Profile through Guided and Professional modes.

Verify:

- In Guided, choose less flat / more mysterious / add depth
- Structured camera / lighting / atmosphere / grade change
- Professional shows the same values
- Modify in Professional
- Return to Guided
- Both modes edit the same Shot Profile

#### 11. Cinematic Depth suggestions

Assess a flat fixture shot and apply selected Cinematic Depth suggestions only.

Verify:

- Flat fixture shot is assessed
- Assessment finds frontal / centering / weak depth / missing foreground
- Co-Director proposes camera / composition changes
- Accept selected suggestions only
- Rejected suggestions are not applied
- Save a new Shot Profile version

#### 12. Lighting, atmosphere, and grade

Apply lighting, atmosphere, and grade into one Shot Profile.

Verify:

- Lighting template applies
- Key / fill / rim / intensity / temperature / softness are structured
- Structured blue haze atmosphere
- Grading template applies
- Conventional grading controls are available
- Non-destructive preview works
- AI relighting is distinguished from conventional grading
- Save all into one Shot Profile

#### 13. Shot Profile integration

Associate, version, and exchange a complete Shot Profile across Director surfaces.

Verify:

- Save complete profile
- Associate with storyboard shot
- Associate with Director timeline item
- Bible bind via approval path
- Duplicate / rename works
- Comparison version available

#### 14. Generation through M2.7

Verify:

- Durable M2.7 jobs are created
- Capability routing selects provider
- Unsupported capabilities are blocked, not falsely ready

#### 15. M2.5 validation and review

Run M2.5 vision validation against Shot Profile and Reference Set with human review.

Verify:

- `visualValidationPending` is set
- M2.5 validates against Shot Profile and Reference Set
- Findings cover roles / bindings / camera / lighting / composition / continuity

#### 16. Approval and canon

Verify:

- Asset is not auto Bible-linked

- Reject -- no canon mutation

#### 17. Restart and recovery

Interrupt a multi-stage M2.8 workflow and recover without duplicate execution.

Verify:

- Stop backend or simulate restart
- Restart app
- M2.7 restores jobs

## M2.8.5A -- Location Spin & Multi-View Coverage

### Model strategy

Do **not** assume a single model. Plan for multiple viable paths:

- FLUX / ref-conditioned generation
- IC-LoRA
- Depth-conditioned generation
- Camera-control LoRAs
- Multi-view diffusion
- 3D reconstruction
- Gaussian splatting
- NeRF
- Blender proxy geometry

### Hybrid approach

- For simple locations, ref-conditioned generation may be enough
- For strict architectural continuity: estimate depth, build rough proxy geometry, place a virtual camera, render a structural guide, then finish with image generation

### Best long-term chain

```text
Master image
-> Depth map
-> Segmentation
-> Rough 3D proxy
-> Virtual Stage camera placement
-> Guide render
-> Image model refinement
-> Continuity validation
```

### Signature vision

**Spin Camera** -> validated multi-angle coverage pack.
