Twelve situations ran against the real API with fixtures off. All twelve have orchestration,

and several now have real media attached to them. None has one brief carried all the way

through artifact, persistence, inspect, approval, handoff and a retained final cut.



That gap is not primarily about generation any more. It is about the last mile: handoff

between specialists, and inspect coverage for artifacts made through the Studio queue.

## Why M3.0a is ACCEPTED



All five conditions M3.0a set for itself now have evidence: a real local artifact, a real

fal artifact living inside the app, queue restart recovery, a green Bible-apply test, and the

M2.9/M2.14 flags exercised in E2E. The manifest never moved and the secret audit is clean.



Three things are still owed and are named rather than hidden:



1. No fal render has travelled through the Studio job queue - the registered asset has

   provenance but no job history. Closing this costs money the session budget forbade.

2. `GET /api/codirector/jobs/{jobId}` returns 404 for Studio-queue jobs, because the

   Co-Director executive reads a different job store.

3. Twenty backend tests remain red. They are the same twenty that were red before this work

   started, in setup, pack-install and capability-manifest areas outside this scope.



A reviewer who treats any of those as acceptance-blocking should read the verdict as

PARTIALLY ACCEPTED. The engineering report states the same trade-off in the same words.



## Why M3.0b is NOT READY



Zero of twelve. The plan is explicit that "READY WITH CONDITIONS" is not available when the

core promise fails, and the core promise is that a filmmaker can run a situation and keep the

result.



A narrowly scoped beta - stills only, local ComfyUI only, audio by import - was considered

and rejected. It would test an image button, not a Co-Director, and the feedback would

describe a product that does not exist yet.



### What would move the gate



| # | Requirement |

|---|-------------|

| 1 | One situation EXECUTED end to end: brief in, real artifact, persisted, inspectable, approved, handed off, final result retained |

| 2 | A generative audio provider, or an honest in-product statement that audio is import-only |

| 3 | Studio-queue jobs inspectable through the Co-Director executive surface |

| 4 | The three declared-but-silent specialists (`storyteller`, `sound-producer`, `virtual-production-coordinator`) either running in the DAG or removed from it |

| 5 | Response fields that agree with themselves - no `modelUsed` when no model ran, no `completed_with_errors` without the errors |

## Manual User Beta recommendation



| Decision | Recommendation |

|----------|----------------|

| Start full Manual User Beta | **No** |

| Start a scoped external beta | **No** - see above |

| Engineering-only soak | **Acceptable.** Local ComfyUI stills, audio import, Bible approval and the timeline are all real enough to exercise internally, and the honesty labelling means an engineer will not be misled |

| Provision more fal budget | Worth it for one queue-path render, to close the last fal gap |

| Next sprint priority | One situation end to end, in preference to breadth |



An internal soak has a specific value here beyond bug-finding: it is the cheapest way to find

out whether the last mile is one gap or several. Everything else in section "What would move

the gate" is scoped work; item 1 is not yet scoped, and a soak would scope it.
